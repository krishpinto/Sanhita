SANHITA — ARCHITECTURE MAP v1.0

a separate system from the transcription pipeline, built from scratch · every box here is deterministic — no AI, no model calls · scroll →
HEALTH WORKER ( opens the app · not a specialist · this is who the whole system is built for )
INDEX CARD INTAKE ( age · sex · vitals if on hand · complaint — picked from a list, or typed and matched against known words · the ONLY free text allowed anywhere, and it's never interpreted, only matched )
DETERMINISTIC PROTOCOL INDEX ( complaint + age → protocol id + version · controlled-vocabulary lookup, not inference · no match → says so honestly, never guesses )
DETERMINISTIC PROTOCOL DEFINITION ( one versioned file per condition · a graph of Steps, each a question + a few answers · authored and reviewed by clinicians · data, not code )
DETERMINISTIC PROTOCOL ENGINE GENERIC INTERPRETER — ZERO MEDICAL KNOWLEDGE ( loads a Protocol Definition · holds the current step + answers so far · shows the question · on answer: records it, resolves next() · same engine runs every protocol you ever write )
DETERMINISTIC DANGER-SIGN INTERRUPT ( any step can mark an answer as a danger sign · checked the instant it's given · short-circuits straight to an urgent outcome, regardless of where you are in the tree )
STEP INPUT TYPES ( choice → tap one button · value → type a number, the step buckets it into a range · "Don't know / n/a" always offered → routes to the safer branch )
OUTCOME ( LIKELY — the probable classification · DO NOW — immediate actions · TELL THE PATIENT — plain-language advice · REFER NOW IF — escalation triggers · FOLLOW UP — safety-net timing · every part cited to a guideline section )
DETERMINISTIC ENCOUNTER RECORD ( protocol id + version · full question+answer trail, timestamped · the outcome reached · every citation · any red flag fired · immutable once written )
FIELD VIEW ( one question, one page · what the health worker uses in the room · nothing else visible, however deep the tree gets )
REVIEW VIEW ( the whole tree at once, like a printed flowchart · what a specialist reads to sign off before a protocol ever goes live · same file as Field View — a different renderer, nothing new modeled )
LEGEND
Teal ring = core, defensible logic
Dashed = reference / note relationship, not a data flow
Orange path = danger-sign shortcut straight to an outcome

Every box on this page is deterministic. There is no AI, no model call, no probabilistic component anywhere in this system — every recommendation is fully reconstructable from the trail alone.

Field View and Review View render the exact same Protocol Definition file. Nothing is duplicated, nothing is kept in sync by hand — there's only one source of truth.

Field View only ever renders the current page — however deep Review View's tree gets, the field interface never gets harder to use. Simplicity is the engine's job; rigor is the content's job.
